# Competition requirements

Checked on October 6, 2026 against the [official rules](https://start-developer-competition-26.devpost.com/rules), [overview](https://start-developer-competition-26.devpost.com/) and [judging criteria](https://start-developer-competition-26.devpost.com/details/judging). These sources govern; this is an implementation checklist.

The entry uses **Productivity / Adapted / Significantly Updated Experience**. Existing work is disclosed, and a substantial new user-facing capability must be delivered during the event. Creating this repository or installing an SDK is not that capability.

| Gate | Evidence needed before submission |
| --- | --- |
| Entrant eligibility | Owner confirmation of age, residence and exclusions; do not commit personal identity documents. |
| Developer access and Start | Owner confirmation that the submitting representative has the required account and membership. |
| Adaptation | Before/after feature log linked to commits and actual demonstrations. |
| Hands | A complete run without controllers, including onboarding, navigation, comparison and notes. |
| English | Review the final UI, instructions, description and video/subtitles. The inherited editor contains Polish text. |
| Rights and branding | Audit dependencies/assets and remove commercial identifiers and recognizable branded products from the experience. |
| Meta policies | Record a review of the policies referenced in the official rules. |
| Function and performance | Real-device measurements; the judging criteria specify at least 60 fps on Quest. |
| Playable access | A freely accessible WebXR URL or the specified APK release channel/invite. |
| Video | Public YouTube/Vimeo demonstration shorter than 180 seconds; actual device or emulator footage. |
| Form | Complete Devpost entry and a clear account of new features. |
| Freeze | Immutable submitted commit/assets, retained access throughout judging. |

Seated interaction, a compact physical reach and a satisfying session within ten minutes are design guidelines. Prefer room-point teleportation over forced camera travel. These choices need comfort testing.

`hackathon.json` records pending/verified gates. A verified gate needs a nonempty evidence reference; account checks should reference a dated owner confirmation, not public personal records. Passing repository checks does not mean these gates are complete. Organizer decisions on significance and eligibility remain authoritative.
